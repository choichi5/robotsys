## 1. 이 시뮬레이션이 하는 일

3링크 평면 로봇팔이

1. 똑바로 펴진 자세(y축 방향)에서 출발해서
2. 왼쪽 벽(`x = -1.5`)으로 다가가고
3. 다가가는 동안 툴을 벽에 수직(`φ = 180°`)이 되도록 돌리고
4. `t ≈ 1.30 s`에 벽에 닿은 뒤
5. **벽을 10 N으로 누르면서** 벽면을 따라 아래로 약 0.63 m 미끄러져 내려갑니다.

여기서 핵심은 4~5번입니다. 벽에 닿은 뒤로는
**x 방향은 "위치"가 아니라 "힘"을 제어**하고, y와 φ는 계속 위치를 제어합니다.
이게 하이브리드 힘/위치 제어입니다.

```
        y
        ↑
  ▓▓▓   |
  ▓▓▓   |        ●  ← t=0, 똑바로 펴진 자세 (0, 3)
  ▓▓▓   |        │
  ▓▓▓   |        │
  ▓▓▓ ══╡ ← 접촉 (y≈1.13)
  ▓▓▓   ↓ 미끄러짐 0.63 m
  ▓▓▓ ══╡ ← 최종 (y=0.5), 10 N 유지
  ▓▓▓   |
 ─────────────────────────→ x    지면 y = 0
   x = -1.5
```

## 2. 2자유도에서 무엇이 바뀌었나

| | 2자유도 (`Hybridimpedance_re`) | 3자유도 (여기) |
|---|---|---|
| 관절 | `q11, q12` | `q11, q12, q13` |
| 작업공간 `X` | `[x ; y]` | `[x ; y ; φ]`, `φ = q11+q12+q13` |
| 자코비안 | 2×2 | 3×3 (여전히 정사각) |
| 궤적 | 3차 다항식 | 5차 다항식 |
| 벽 | `x = -0.5` | `x = -1.5` (파라미터 `x_wall`) |
| 지면 | **없음** | `y = 0` (파라미터 `y_ground`) |
| J 역행렬 | `J\(...)` | 감쇠최소자승(DLS) |

바꾼 이유는 각각 아래 섹션에서 설명합니다.

## 3. 작업공간을 [x, y, φ]로 잡은 이유

관절이 3개니까 작업공간 변수도 3개를 잡을 수 있습니다. 선택지가 둘 있었습니다.

**(A) `X = [x, y, φ]` — 채택**
엔드이펙터 위치 2개 + 자세각 1개. `φ = q11+q12+q13`은 평면에서
"툴이 어느 방향을 보고 있는가"입니다. 자코비안이 **3×3 정사각**이 되므로,
2자유도에서 쓰던

```matlab
dd_q = J \ (dd_x - dJ*dQ);
```

이 구조가 **그대로** 유지됩니다.

**(B) `X = [x, y]` — 여유자유도**
관절 3개로 2차원 작업공간을 제어하면 자유도가 하나 남습니다(여유자유도).
`pinv(J)`와 널스페이스 항(관절 한계 회피 등)이 필요해서 제어기 구조를
크게 손봐야 합니다.

(A)가 기존 코드와의 연속성이 훨씬 좋아서 (A)로 갔습니다.
벽을 누르는 작업에서는 "툴을 벽에 수직으로 유지"라는 자연스러운 φ 목표도 있고요.

### 순기구학

```
x = L1·cos(q1) + L2·cos(q1+q2) + L3·cos(q1+q2+q3)
y = L1·sin(q1) + L2·sin(q1+q2) + L3·sin(q1+q2+q3)
φ = q1 + q2 + q3
```

φ의 자코비안 행이 `[1 1 1]`인 이유가 여기 있습니다 — φ는 그냥 관절각의 합입니다.

## 4. 동역학 — H, S, G, J, dJ

로봇 동역학 방정식은

```
H(q)·q̈ + S(q,q̇) + G(q) = τ + Jᵀ·F_ext
```

- `H` : 관성행렬 (3×3)
- `S` : 코리올리/원심력 벡터 (3×1)
- `G` : 중력 벡터 (3×1)
- `τ` : 관절 토크
- `F_ext` : 외력(접촉력)

### 4.1 관성행렬 H

3링크 평면팔의 H는 **6개의 묶음 파라미터**로 깔끔하게 정리됩니다:

```matlab
a1 = I1 + m1·lc1² + (m2+m3)·L1²
a2 = I2 + m2·lc2² + m3·L2²
a3 = I3 + m3·lc3²
b1 = L1·(m2·lc2 + m3·L2)      % q1-q2 결합, cos(q2)
b2 = m3·L2·lc3                % q2-q3 결합, cos(q3)
b3 = m3·L1·lc3                % q1-q3 결합, cos(q2+q3)
```

```
H11 = a1+a2+a3 + 2b1·c2 + 2b2·c3 + 2b3·c23
H12 = a2+a3 + b1·c2 + 2b2·c3 + b3·c23
H13 = a3 + b2·c3 + b3·c23
H22 = a2+a3 + 2b2·c3
H23 = a3 + b2·c3
H33 = a3
```

H는 대칭이라 6개만 쓰면 됩니다. `c2 = cos(q2)`, `c23 = cos(q2+q3)` 등.
**H가 q1에 의존하지 않는 것**에 주목하세요 — 1번 관절을 돌려도 팔 전체 형상은
그대로라 관성이 안 바뀝니다. 이 성질이 다음 절에서 계산을 줄여줍니다.

### 4.2 코리올리 항 S — 왜 손으로 안 풀었나

2자유도에서는 S가 항이 2개뿐이라 손으로 전개할 만합니다:

```matlab
S1 = -2·dq1·dq2·L1·lc2·m2·sin(q2) - dq2²·L1·lc2·m2·sin(q2);
S2 = dq1²·L1·lc2·m2·sin(q2);
```

3자유도가 되면 항이 수십 개로 늘어나서 손으로 전개하면 실수하기 딱 좋습니다.
그래서 **제1종 크리스토펠 기호(Christoffel symbols)** 정의를 코드로 그대로
옮겼습니다:

```
c_ijk = ½ ( ∂H_ij/∂q_k + ∂H_ik/∂q_j − ∂H_jk/∂q_i )
S_i   = Σ_j Σ_k  c_ijk · q̇_j · q̇_k
```

`∂H/∂q`는 H가 cos 몇 개뿐이라 해석적으로 간단합니다.
`∂H/∂q1 = 0` (위에서 말한 성질), 나머지 둘만 쓰면 됩니다:

```matlab
dH1 = zeros(3,3);                      % H는 q1에 무관
dH2 = [ ... -b1·s2, -b3·s23 항들 ... ];  % ∂H/∂q2
dH3 = [ ... -b2·s3, -b3·s23 항들 ... ];  % ∂H/∂q3
dH  = cat(3, dH1, dH2, dH3);

for i=1:3, for j=1:3
    C(i,j) = Σ_k 0.5*(dH(i,j,k)+dH(i,k,j)-dH(j,k,i))*dQ(k);
end, end
Matrix_S = C*dQ;
```

**검증**: 이 크리스토펠 코드에 2링크 파라미터를 넣으면 위의 2자유도
손계산 식과 정확히 일치합니다. 그리고 3링크 전체는 유한차분으로 만든
라그랑주 모델과 대조해서 최대 오차 `6e-5`로 확인했습니다.

### 4.3 중력 G

위치에너지 `V = Σ mᵢ·g·yᵢ`를 관절각으로 편미분한 것입니다.

```
G1 = g·[ m1·lc1·c1 + m2·(L1·c1 + lc2·c12) + m3·(L1·c1 + L2·c12 + lc3·c123) ]
G2 = g·[ m2·lc2·c12 + m3·(L2·c12 + lc3·c123) ]
G3 = g·[ m3·lc3·c123 ]
```

`sin`을 미분해서 `cos`이 나온 것이니, `cos`이 보인다고 당황하지 마세요.

### 4.4 자코비안 J와 그 시간미분 dJ

```
J = [ -L1·s1-L2·s12-L3·s123 ,  -L2·s12-L3·s123 ,  -L3·s123
       L1·c1+L2·c12+L3·c123 ,   L2·c12+L3·c123 ,   L3·c123
       1                    ,   1              ,   1        ]
```

`dJ`는 각 항을 시간으로 미분한 것으로, 누적 각속도
`w1 = dq1`, `w12 = dq1+dq2`, `w123 = dq1+dq2+dq3`가 곱해집니다.
`dJ`의 3행은 상수 `[1 1 1]`을 미분한 것이라 전부 0입니다.

`dJ`가 필요한 이유: `Ẍ = J·q̈ + J̇·q̇` 이므로, 원하는 작업공간 가속도
`dd_x`에서 관절가속도를 뽑으려면 `J̇·q̇`를 빼줘야 합니다.

```matlab
dd_q = J \ (dd_x - dJ*dQ);
```

## 5. 하이브리드 힘/위치 제어

### 왜 방향을 나누나

벽을 누르면서 벽면을 따라 움직이려고 합니다. 그런데

- **벽에 수직인 방향(x)** 은 위치를 제어할 수 없습니다. 벽이 딱딱해서
  아무리 "x = -2.0으로 가라"고 해도 `x = -1.5`에서 멈춥니다.
  대신 **얼마나 세게 누를지(힘)** 는 제어할 수 있습니다.
- **벽에 나란한 방향(y)** 은 반대로 힘을 제어할 게 없고
  (자유롭게 움직이니까) **위치**를 제어하면 됩니다.

이렇게 방향별로 무엇을 제어할지 나누는 게 하이브리드 제어입니다.

### 실제 제어식 (`Dynamics.m`)

**접촉 중** (`xf < x_wall`):

```matlab
% x : 힘 제어 (F_d = 10 N 을 유지)
dd_xf = ddxdf + K_mf*( K_df*(dxdf-dxf) - A_f*(F_d-f_ext_x) - B_f*Intf );

% y : 위치 제어 (벽을 따라 미끄러짐)
dd_xp = ddxdp + K_mp*( K_dp*(dxdp-dxp) + K_pp*(xdp-xp) );

% φ : 위치 제어 (툴을 벽에 수직으로 유지)
dd_xo = ddxdo + K_mo*( K_do*(dxdo-dxo) + K_po*(xdo-xo) );
```

x 식에서
- `A_f*(F_d - f_ext_x)` : 힘 오차에 대한 **비례(P)** 항
- `B_f*Intf` : 힘 오차의 **적분(I)** 항.
  `Intf`는 Simulink의 Integrator1 블록이 `F_d - f_ext_x`를 적분한 값입니다.
  정상상태 힘 오차를 0으로 만드는 역할을 합니다 — 실제로 최종 `Fx = 10.0000 N`.

**비접촉 중**: 세 방향 모두 일반적인 계산토크(computed torque) 제어

```matlab
dd_x = ddXd + K_m*( K_d*(dXd-dX) + K_p*(Xd-X) - F_ext );
```

### 그 다음 단계

```matlab
dd_q  = J \ (dd_x - dJ*dQ);                       % 작업공간 → 관절공간
τ     = H*dd_q + S + G - Jᵀ*F_ext;                % 계산 토크
ddQ   = H \ (τ - S - G + Jᵀ*F_ext + Tau_g);       % 실제 관절 가속도
```

`τ`에서 `Jᵀ·F_ext`를 빼고 `ddQ`에서 다시 더하는 것은
**접촉력을 피드포워드로 상쇄**하는 것입니다. 그래서 `Tau_g = 0`이면
`ddQ = dd_q`가 정확히 성립합니다 — 접촉력이 추종 성능을 망치지 않습니다.

## 6. 벽 접촉 모델

벽은 페널티(penalty) 모델입니다. 벽 안으로 들어간 깊이에 비례하는
아주 센 스프링 + 감쇠로 밀어냅니다.

```matlab
if xf < x_wall
    f_ext_x = -( 1e6*(xf - x_wall) + 1e2*dxf );   % 수직항력
    f_ext_y = -mu * dxp;                          % 마찰 (mu = 20)
    n_ext_z = 0;                                  % 점접촉 → 접촉 모멘트 없음
end
```

- `1e6`은 **벽의 강성**입니다. 매우 딱딱한 벽이라는 뜻이고,
  10 N을 누를 때 실제 침투량은 `10/1e6 = 1e-5 m` 정도로 무시할 수준입니다.
- `1e2*dxf`는 접촉 감쇠. 없으면 충돌할 때 계속 튕깁니다.
- 마찰 `f_ext_y = -mu·ẏ`는 미끄러질 때 위로 저항하는 힘입니다.
  그래프에서 `t = 1.3~2.0 s` 구간의 `F_y`가 이것입니다.

접촉 순간 `Fx`가 **121.8 N**까지 튀는데, 이건 충돌 과도응답입니다.
정상상태로 가면 10 N으로 정착합니다.

## 7. 지면 접촉 모델

### 왜 필요했나

원래 2자유도 모델에는 지면이 아예 없었습니다. 그래서 3자유도로 늘렸을 때
팔꿈치가 `y = -0.41`까지, 즉 **바닥을 뚫고** 내려갔습니다.

### 왜 엔드이펙터만으로는 안 되나

벽 접촉은 툴 끝에서만 일어나지만, 지면은 **팔의 어느 부분이든** 닿을 수
있습니다. 실제로 문제가 됐던 것도 툴이 아니라 팔꿈치였습니다.
그래서 링크마다 **중점과 끝점 2개씩, 총 6개 접촉점**을 잡았습니다.

### 구현

```matlab
for k = 1:3                          % 링크
  for frac = [0.5 1.0]               % 중점, 끝점
    p = (그 점의 위치);
    if p(2) < y_ground
        Jp    = (그 점의 위치 자코비안, 2×3);
        vp    = Jp*dQ;
        f_gy  = -( k_g*(p(2)-y_ground) + d_g*vp(2) );
        f_gy  = max(f_gy, 0);        % ★ 지면은 밀기만 하고 당기지 않는다
        f_gx  = -mu_g*vp(1);
        Tau_g = Tau_g + Jp'*[f_gx; f_gy];
    end
  end
end
```

두 가지 포인트:

1. **`max(f_gy, 0)`** — 단방향(unilateral) 구속. 감쇠항 때문에 빠르게
   위로 튀어오를 때 힘이 음수가 되어 지면이 팔을 *잡아당기는* 비물리적
   현상이 생길 수 있어 0으로 잘랐습니다.
2. **`Tau_g`는 제어기가 모릅니다.** `ddQ` 계산에만 더해지고 `τ` 계산에는
   안 들어갑니다. 예기치 못한 충돌은 제어기가 미리 알 수 없으므로
   이게 물리적으로 맞습니다.

### 검증

현재 궤적은 지면 근처로 가지 않기 때문에(팔꿈치 최저 0.74 m) 이 코드가
실제로 도는지 확인하려면 일부러 시험해야 합니다.
**툴을 `y = -0.8`로 명령**해 봤더니 팔이 `-0.77 mm`에서 멈추고
팔꿈치와 툴이 바닥에 얹혔습니다. 통과하지 않습니다.

(`-0.77 mm`는 페널티 모델의 침투량입니다. 지면 강성 `k_g = 1e6`에
팔 무게 + 제어기가 계속 아래로 미는 힘이 걸린 결과입니다.)

## 8. 특이자세 문제와 해결

### 문제

"완전히 펴진 자세로 시작하고 싶다"는 요구는 자연스럽지만,
**완전히 펴진 평면 로봇팔은 특이자세(singular configuration)** 입니다.

`q = (90°, 0°, 0°)`에서 자코비안을 계산해 보면

```
J = [ -3  -2  -1
       0   0   0        ← 2행이 전부 0
       1   1   1 ]
```

`det J = 0`. 물리적으로는 **팔이 자기 축 방향(여기서는 y 방향)으로
가속할 수 없다**는 뜻입니다. 쭉 편 팔을 더 길게 늘릴 수는 없으니까요.

`J \ (...)`는 여기서 정의되지 않고, 실제로 첫 실행은
`행렬이 특이 행렬입니다` 오류로 죽었습니다.

### 해결 1 — 5차 다항식 궤적

3차 다항식은 `t=0`에서 속도는 0이지만 **가속도는 0이 아닙니다**:

```
s(τ)   = 3τ² - 2τ³
s̈(0)   = 6/T² ≠ 0        ← t=0 에 가속도를 요구함
```

특이자세에서 가속도를 요구하면 무한대 관절가속도가 나옵니다.
5차 다항식은 시작과 끝에서 속도·가속도가 **모두** 0입니다:

```
s(τ)   = 10τ³ - 15τ⁴ + 6τ⁵
s̈(0)   = 0    ✓
s̈(1)   = 0    ✓
```

그래서 `J`가 랭크 부족인 동안에는 아무것도 요구하지 않고,
팔이 조금 움직여 특이자세를 벗어난 뒤부터 본격적으로 가속합니다.

### 해결 2 — 감쇠최소자승(DLS) 역행렬

그래도 특이자세 *근처* 에서는 `J`의 최소 특이값이 작아 관절속도가 폭발합니다.
최소 특이값이 문턱값 아래로 내려가면 감쇠를 섞습니다:

```matlab
eps_dls = 0.10;
lam_0   = 0.05;
sig_min = min(svd(Matrix_J));
if sig_min < eps_dls
    lam2 = lam_0^2*(1 - (sig_min/eps_dls)^2);
else
    lam2 = 0;
end
dd_q = (J'*J + lam2*eye(3)) \ (J'*(dd_x - dJ*dQ));
```

**특이자세에서 멀면 `lam2 = 0`이 되어 원래 식과 정확히 같습니다.**
즉 평소 동작에는 아무 영향이 없고, 위험할 때만 개입합니다.

같은 이유로 `controller.m`은 `inv(J)` 대신 `pinv(J)`를 쓰고,
`FF`(접촉 렌치 재계산)도 같은 감쇠 역행렬을 씁니다.

## 9. Simulink 모델 구조

```
 Clock ──→ desired ──────────┐
                             │
 (Direct Kinematics: X, dX) ─┼→ Mux [9 6 6 1] = 22 ──→ controller ──→ Robot Dynamics
 (Integrator: q, dq) ────────┤                            (22)            (19)
```

## 12. 튜닝 포인트

`Dynamics.m` 안에 다 모여 있습니다.

| 파라미터 | 현재값 | 의미 | 바꿔보면 |
|---|---|---|---|
| `F_d` | 10 | 목표 접촉력 [N] | 크게 하면 더 세게 누름 |
| `A_f` | 10 | 힘 오차 비례 게인 | 크면 빠르지만 진동 |
| `B_f` | 100 | 힘 오차 적분 게인 | 정상상태 오차 제거 |
| `mu` | 20 | 벽 마찰 계수 | 0이면 마찰 없이 미끄러짐 |
| `K_pp`, `K_po` | 100 | y, φ 위치 게인 | |
| `K_dp`, `K_do` | 1 | y, φ 속도 게인 | **아래 참고** |
| `k_g`, `d_g`, `mu_g` | 1e6, 1e2, 20 | 지면 강성/감쇠/마찰 | |
| `eps_dls`, `lam_0` | 0.10, 0.05 | DLS 문턱값/감쇠 | |

### 알아둘 만한 것 (2자유도에서 그대로 가져온 값들)

**1. 접촉 중 y 루프가 감쇠 부족입니다.**
`K_pp = 100`, `K_dp = 1`이면

```
ωn = √100 = 10 rad/s
ζ  = K_dp / (2·ωn) = 1/20 = 0.05
```

`ζ = 0.05`는 매우 언더댐프드입니다. 3번 그래프에서 `t = 2 s` 이후
`Fy`가 계속 흔들리는 게 이것입니다. **`K_dp`를 10 근처로 올리면**
임계감쇠가 되어 깔끔해집니다. 자유도 확장과는 무관한 재튜닝이라
원본 값을 그대로 뒀습니다.

**2. 자유공간 게인의 주석이 뒤바뀌어 있습니다.**
`K_d = 100`이 **속도** 오차에, `K_p = 1`이 **위치** 오차에 곱해집니다.
원본 파일의 주석 헤더(`Proportional` / `Derivative`)가 실제 사용과
반대로 붙어 있습니다. 값은 건드리지 않았습니다.

**3. 원본과 달라진 부분 두 군데**
- `desired.m`: `T_final` 이후 속도·가속도 피드포워드를 0으로 강제.
  원본처럼 다항식을 `t = T_final`에서 그대로 평가하면 `s̈ = -1.5`가 남아,
  동작이 끝난 뒤에도 가속도 명령이 계속 걸립니다.
- `circle.m`: 가속도 식에 빠져 있던 구심항(`-r·cos(ω)·ω̇²`)과 `r` 계수 보정.

## 13. 자주 나는 오류

**`행렬이 설정된 작업 정밀도에서 특이 행렬입니다`**
초기자세가 특이자세인데 DLS를 안 쓰고 `J\(...)`나 `inv(J)`를 쓴 경우입니다.
`init.m`의 초기 관절각을 바꿨다면 그 자세가 특이한지 확인하세요.
평면팔은 **완전히 펴지거나 완전히 접힌** 자세가 특이자세입니다.

**`유효하지 않는 출력이 발생했습니다 (Inf/NaN)`**
위와 같은 원인이거나, 목표 궤적이 작업공간(`reach = 3 m`) 밖입니다.
`desired.m`의 `x_f`, `y_f`가 도달 가능한지 확인하세요.
`φ = 180°`로 고정하면 손목 위치는 `(x_f + 1, y_f)`가 되고,
이 점까지의 거리가 2 이하여야 합니다.

**신호 폭 불일치 (`Mux`/`Demux` 오류)**
`.mdl`의 폭을 하나라도 빠뜨린 경우입니다. 9번 섹션의 표와 대조하세요.

**`x_wall`을 바꿨는데 애니메이션 벽이 그대로**
`test_avi.m` 안의 `x_wall_p`, `y_ground_p`는 그림용 로컬 변수라
따로 맞춰줘야 합니다.

**팔이 지면 아래로 내려감**
목표 자세가 지면 위에 있어도, 팔꿈치가 아래로 향하는 해(elbow-down)로
수렴하면 링크가 지면을 침범할 수 있습니다. 지면 접촉이 막아주긴 하지만
그 상태에서는 추종 성능이 나빠집니다. 초기자세를 바꿔서
elbow-up 해로 유도하는 게 낫습니다.
